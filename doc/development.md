# Development and release

Everything runs headless — no GUI needed, which is why the whole regression suite fits in CI.

See also: [`design.md`](design.md) for the data model.

## Requirements

Blender **5.2 LTS** (`blender_version_min = "5.2.0"`). CI verifies 5.2.4 only; 4.2 / 4.5 / 5.0
are not covered and therefore not declared.

## Headless tests

Run with the repository on `sys.path` (the checkout directory name equals the package name):

```bash
blender -b --factory-startup -P tests/roundtrip.py -- --fixtures   # import → export, byte identical
blender -b --factory-startup -P tests/roundtrip.py -- --raw        # same, raw aircraft axes
blender -b --factory-startup -P tests/mutation.py                  # new attachment, inserted field
blender -b --factory-startup -P tests/origin.py                    # origin resolution + axis round trip
blender -b --factory-startup -P tests/duplicate.py                 # Shift+D copy becomes a new attachment
blender -b --factory-startup -P tests/events.py                    # 1:N grouping and rename
blender -b --factory-startup -P tests/spaces.py                    # sound spaces: geometry, write-back, creation
blender -b --factory-startup -P tests/align_mesh.py                # distance to cockpit surfaces
```

`tests/align_mesh.py` prefers the real `io_scene_xplane_obj` importer when it is installed and
otherwise falls back to its own OBJ8 parser plus the same transform, so CI needs no add-ons.

Static checks without Blender:

```bash
python3 tests/ci_lint.py          # syntax, manifest fields, UTF-8 on text files, no build artifacts
python3 tests/make_fixtures.py    # regenerate fixtures; CI asserts they do not drift
```

Fixtures under `tests/fixtures/` are synthetic (no Laminar content) and regenerated by
`make_fixtures.py`; CI fails if the committed files differ from a fresh run.

## Build

```bash
mkdir -p dist
blender --factory-startup --command extension build --source-dir . --output-dir dist
blender --factory-startup --command extension validate dist/io_scene_xplane_snd-*.zip
```

`--output-dir` must exist. Files listed under `[build] paths_exclude_pattern` are kept out of
the archive — that list *replaces* the built-in defaults, so `/.git/`, `/tests/`, `/doc/`,
`/branding/`, `/dist/` and `__pycache__/` all have to be named explicitly. CI asserts the
resulting zip: manifest, `LICENSE` and `__init__.py` at the root, no dev directories, and no
review-sensitive code patterns (`sys.path` manipulation, `bl_ext` literals, imports of other
add-ons).

## Release

Tag an annotated `v<manifest version>` and push. The workflow then:

1. runs `ci_lint`, fixtures drift check, build, validate, package assertions, install into an
   isolated extensions directory, and the full headless suite on Blender 5.2.4;
2. creates a **draft** GitHub release carrying `io_scene_xplane_snd-<version>.zip`, with the
   tag annotation as release notes.

```bash
git tag -a v0.1.9 -m "release notes…"
git push origin main && git push origin refs/tags/v0.1.9
```

Publishing the draft is a manual step. If the release job reports 403, enable
*Settings ▸ Actions ▸ General ▸ Workflow permissions ▸ Read and write*.

Rules that keep versions honest:

- the manifest `version` is the only version string; the tag must match it;
- a published number is spent: any content change bumps it, including metadata-only edits
  requested by review;
- a tag that is already pushed is never re-pointed — bump and tag again;
- a tag whose CI fails leaves that version without an artifact; fix, bump, retag.

## Repository layout

```
__init__.py          registration, import/export menu entries
document.py          .snd model: raw lines, attachments, sound spaces, line patch
operators.py         import / export / selection / sound-space creation operators
spaces.py            sound-space visualisation and write-back
acftool.py           origin resolution, axis mapping
filehandlers.py      drag-and-drop of .snd
ui.py                sidebar panel
tests/               headless suite + synthetic fixtures
doc/                 documentation (not shipped)
branding/            store icon sources (not shipped)
```
